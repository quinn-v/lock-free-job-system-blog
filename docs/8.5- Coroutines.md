***

As a bonus, the co-routine machinery makes it straightforward to switch which executor a co-routine runs on mid-execution.

This comes up when you want a co-routine to do IO-bound work on a dedicated IO thread pool, then return results to the main compute pool- or when you need a final step to run on a specific thread (e.g. the render thread in a game engine).

***

**RunOnExecutor**

The `RunOnExecutor` awaitable re-enqueues the current co-routine on the given executor, then suspends. The executor will resume it as a normal task:

```cpp
struct RunOnExecutor final
{
    IExecutor *executor;

    bool await_ready() const noexcept { return false; }

    void await_suspend(std::coroutine_handle<> caller) const
    {
        TaskRef ref{
            .ptr = caller.address(),
            .function = [](void *addr)
            {
                std::coroutine_handle<>::from_address(addr).resume();
            },
        };
        executor->enqueue(ref);
    }

    void await_resume() const noexcept {}
};
```

After `co_await RunOnExecutor{&other_pool}`, the co-routine continues on a worker from `other_pool`. The current worker is free to pick up other tasks immediately.

***

**resume_on**

A complementary helper on `Task<T>` lets you set the target executor for the *continuation*-the co-routine that's awaiting this task. When the task completes, rather than resuming the caller inline via symmetric transfer, it re-enqueues it on the specified executor:

```cpp
Task<int> compute_on_io()
{
    co_await RunOnExecutor{&io_pool};
    co_return fetch_data();
}

Task<void> main_task()
{
    // this coroutine will be resumed on compute_pool when compute_on_io() finishes
    int result = co_await compute_on_io().resume_on(&compute_pool);
}
```

Under the hood, `resume_on` stores the executor pointer in the promise via `set_continuation_executor`:

```cpp
Task &
resume_on(IExecutor *executor) & noexcept
{
    handle_.promise().set_continuation_executor(executor);
    return *this;
}
```

`FinalAwaiter` then sees the stored executor and enqueues the continuation rather than symmetric-transferring into it:

```cpp
if (promise.continuation_)
{
    if (promise.continuation_executor_)
    {
        enqueue_handle(promise.continuation_executor_, promise.continuation_);
        return std::noop_coroutine();
    }
    return promise.continuation_;
}
```

The two mechanisms compose: `RunOnExecutor` migrates the current coroutine to a new executor, while `resume_on` migrates its caller when this coroutine completes.
