***

With the allocator in place, we can implement the full cancellable task type introduced in section 3.5.

`CancellableTask` holds the task body, the allocator it was allocated from, and a `std::stop_token` to observe. It does not hold the `stop_source`- the source lives in the returned `CancellationHandle`. The task needs to observe, not request; holding only the token also prevents the task from accidentally cancelling itself.

```cpp
template <typename Body, Allocator Alloc, typename Destroyer = AllocatorDestroyer>
class CancellableTask final
{
  public:
    CancellableTask(std::stop_token token, Alloc *alloc, Body &&body) :
        _token(std::move(token)),
        _alloc(alloc),
        _body(std::forward<Body>(body))
    {
    }

    [[nodiscard]] IAllocator *
    get_allocator() const noexcept { return _alloc; }

    [[nodiscard]] TaskRef
    as_ref() { return TaskRef::create(this); }

    void
    operator()()
    {
        if (_token.stop_requested())
        {
            Destroyer{}(this);
            return;
        }

        if constexpr (std::is_invocable_v<Body &, std::stop_token>)
        {
            _body(_token);
        }
        else
        {
            _body();
        }

        Destroyer{}(this);
    }

  private:
    std::stop_token _token;
    Body _body;
    Alloc *_alloc;
};
```

When the task executes, it checks the token first. If cancellation was already requested, it destroys itself and returns without calling the body. Otherwise it calls the body- passing the token if the body accepts one - then destroys itself. The `Destroyer` routes deallocation to the correct path: `deallocate` if the executing thread owns the allocator, `ts_deallocate` if it is a thief thread.

The enqueue function creates the source and token, allocates the task through the thread-safe allocator path (since it may be called from any thread), and returns the handle to the caller:

```cpp
template <typename Body>
CancellationHandle
enqueue_cancelable(IExecutor &exec, Body &&body)
{
    std::stop_source source;
    std::stop_token token = source.get_token();

    IAllocator *alloc = exec.allocator();
    using TaskT = CancellableTask<std::decay_t<Body>, std::decay_t<decltype(*alloc)>>;
    auto *task = alloc->template ts_create<TaskT>(token, alloc, std::forward<Body>(body));

    if (task == nullptr)
    {
        return {};
    }

    if (!exec.enqueue(task->as_ref()))
    {
        alloc->ts_destroy(task);
        return {};
    }

    return CancellationHandle(std::move(source));
}
```

`ts_create` is used because `enqueue_cancelable` may be called from any thread. The `source` is moved into the returned handle; the task holds the `token`. Both share the same stop state through `std::stop_source`'s internal reference count - no extra allocation.

Usage:

```cpp
auto handle = enqueue_cancelable(pool, [](std::stop_token tok)
{
    while (!tok.stop_requested())
    {
        do_incremental_work();
    }
});

// Later, from any thread:
handle.cancel();
```

An empty `CancellationHandle` (returned when enqueueing fails) converts to `false` via `operator bool`, so callers can check the return value before calling `cancel()`.
