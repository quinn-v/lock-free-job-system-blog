It can be useful to have cancellation support for your tasks.
I will be implementing this through the addition of a new task type, since it comes with a bit of overhead for tasks that don't need it.

`std::stop_source` and `std::stop_token` from C++20 work very well here.
The caller keeps a `CancellationHandle`, which owns the `stop_source`. The task will hold the corresponding `stop_token`, extracted at enqueue time. This allows you to easily signal the stop token through the handle.

```cpp
class CancellationHandle
{
  public:
    CancellationHandle() : _source(std::nostopstate) {}

    explicit CancellationHandle(std::stop_source source) :
        _source(std::move(source))
    {
    }

    void
    cancel() noexcept
    {
        if (_source.stop_possible())
        {
            _source.request_stop();
        }
    }

    [[nodiscard]] bool
    is_cancelled() const noexcept
    {
        return _source.stop_possible() && _source.stop_requested();
    }

    [[nodiscard]] explicit
    operator bool() const noexcept
    {
        return _source.stop_possible();
    }

  private:
    std::stop_source _source;
};
```

The default constructor uses `std::nostopstate`- a tag that creates a `stop_source` with no associated stop state. `stop_possible()` returns false for this, so `operator bool` correctly returns false for an empty handle. This is used as the "enqueueing failed" return value.

Cancelling a task doesn't remove it from the queue- it will still be dequeued, checked, and then skipped. If you want to cancel tasks while they are running, accept a `std::stop_token` as the first parameter and check it at periodic points.
